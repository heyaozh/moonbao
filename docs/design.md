## 1. 它是谁

一个小小的月亮，住在你手机的夜空里。安静、憨憨、话不多、活在当下。它不说话——用眼神、光、动作和星星拼出的字回应你。它记得你说过的话，第二天会想起来问你。你可以在它身上画花纹，它会一直留着。

定位：电子陪伴，不是 AI 女友，不是心理健康工具。「被一个小生命惦记着」是它给人的核心感受。

三个侧重点（✅ 用户定）：**记忆、动画效果、低延迟**。

### 为什么是月亮
- 几乎刚体、没有四肢、没有蒙皮——**整个角色能实时程序化**，不需要 AI 视频管线，不需要外包美术，零素材体积、零身份漂移、零片段延迟、完全可交互。
- 表情载体只有眼睛 + 运动曲线 + 光。这是约束也是好处：可爱度不靠几何复杂度。
- 天然和「夜空 / 时间 / 天气」绑定，背景与角色是一体的世界。

### 诚实的短板（立项时就知道）
- IP 独创性低：月亮是通用符号，护城河只能来自角色的 specificity（眼神、性格、它的星星、它身上你画的纹）。
- 月相由天文决定，不属于用户 → 成长机制必须另外给（见 §6「画花纹」）。

## 2. 外形与动画（可爱度从哪来）

- **眼睛**：两颗黑豆眼，会眨。位置在月面高度的 **40~55%**（不是几何中心），间距约 **0.5 个月亮宽**——婴儿图式。
- **眨眼 timing 就是人格**：双眨（惊讶）、慢眨（信任 / 困）、眯成 `^ ^`（笑）、变 `· ·`（呆）、眼珠下移（心虚）。豆豆眼的形状可以做少量离散表情，不需要嘴和眉毛。
- ✅ **放弃完全刚体**：±4% 左右的 squash & stretch——停下 / 落地 / 被戳时压扁再弹回。顶点级形变，几乎零成本，是可爱的必要条件。
- **弹簧阻尼比 ζ≈0.4~0.6**（过冲一点再回来），不要临界阻尼。这个数字比任何美术调整都更决定「它是不是活的」。
- **被动运动服从物理，主动运动轻微违反物理**：想过来时先往后缩一点蓄力再冲过来（anticipation）。这是「满足物理规律又有主观能动性」的准确表达。
- ✅ **朝向（2026-09-26 改）**：脸（眼、嘴、腮红）**固定在球面上**，整个月亮转过来看你——纹理和表情一起转，不是表情在表面上漂移（用户：「感觉是月亮在转动看着用户」）。月相的光在世界坐标里不动。翻滚时脸自然转到背面 = 「害羞地转过去」，是真的物理转动。取代旧的「眼睛所在的面 billboard 永远朝向用户」。
- 动作词汇（`shared/protocol.ts`）：idle_drift / lean_in / think_tilt / bounce / roll / spin / hide_edge / nod / dim / brighten / shiver / drift_away。全是「位移 / 翻滚 / 光」三类。
- 运动感：缓慢漂浮、翻滚、躲到屏幕外、在移动中缓慢停下再向用户飘来。

### 表情库（2026-09-26，PLAN V2）

### 不聊天的互动（✅ 2026-09-26 用户第 3 点，PLAN V3）
- 没人干预时是零重力：缓慢漂浮、翻滚；人可以和它互动，改变它的动作和轨迹（比如推它）。可以前后左右上下移动，甚至弹来弹去。

## 3. 月相、光与陨石坑

- ✅ **月相 = 光照，不是几何**。几何永远是完整的球，只有一盏方向光在转。轮廓恒为圆形，「一半圆一边不那么圆」的难看形状根本不会出现；不用为每个月相做模型，月相连续。
- **地照（earthshine）**：暗部保留极低亮度的完整轮廓。真实天文现象，而且**地照在蛾眉月附近最强**（那时地球对月亮是「满地球」）——细弯月 + 隐约可见的灰盘正是现实中最美的月相。让地照亮度随月相反向变化：既保住弯月的味道，又永远不会完全看不见（✅ 用户要求）。
- 眼睛落在暗部时给一点微弱自发光保持可见。
- ✅ **发光 = 光晕 + 地照，不靠表面自发光**（2026-09-23）。look-dev 证明表面自发光从 0.33 档起就吃掉月相、整个盘都亮；光晕（bloom / sprite）+ 地照填光能保住月相又让暗面轮廓永远可见。表面自发光只留 ≤0.2 一档保证暗面轮廓。发光默认档 = look-dev soft 模式的 1.0（用户 2026-09-23 选定，对照见 `assets/moon/nasa_face_softglow/contact_sheet.png`）。素材与对照见 `assets/moon/README.md`。
- ✅ **嘴和腮红常驻**（2026-09-23 用户拍板）：它不需要说话，但可以有表情——嘴形词汇至少「微笑 / o 型（惊讶）/ 平（呆）」，腮红随害羞 / 开心加深。比例按用户给的参考图（`assets/moon/reference/face_reference.jpg`）量得（作 P0 `params.ts` 初值）：眼距 0.54 R、眼 0.12×0.14 R 的哑光黑圆点、眼在球心高度略下 0.02 R；微笑弧宽 0.20 R、在眼下 0.20 R、两端上翘 ≈ 宽的 1/5、线粗 0.02 R；腮红半径 0.085 R、中心离中轴 0.46 R、在眼下 0.14 R、粉色 (1.0, 0.45, 0.55) 中心 55% 不透明向外羽化。渲染对照 `assets/moon/nasa_face_softglow/`。这条修正了 §2「不需要嘴」的旧说法。
- 月相用本地天文算法算，不需要 API。
- **陨石坑**：只出现在脸的外围环带，中央脸区留空，不和眼睛抢注意力。白天可见、夜晚被柔光盖过。
- 💡 **坑的生命周期**：流星是事件（偶发、可观赏的小演出），坑是纪念（中性甚至好看）；**没被画过的坑会慢慢被月尘填平淡去，被画进花纹的坑永久保留**。这是「失忆不对称」（日常可以忘，重要的不能忘）在视觉上的表达，也天然解决坑无限累积糊脸的问题。
- ❌ **「说了某类话就加一个坑」**：陨石坑读作伤痕，由负面话题触发会滑向内疚驱动留存，顶在温柔设计红线上。否决。

## 4. 天空、时间与天气

- 背景色随时间：白天天蓝、傍晚橙、晚上深蓝。**用太阳高度角（纬度 + 日期可算）平滑插值，不要用钟表时间硬切**——否则夏天晚上九点天还亮着屏幕却已深蓝，出戏。
- 晚上它发柔和的光。
- 星星：远处很多安静的小点（程序化）；有几颗调皮的会飞来飞去像小朋友；偶尔刷新极光（domain-warped noise + 垂直渐变 + additive，纯 shader，成本近零）。
  - ✅ **远星几乎不动**（2026-09-23 用户）：真实的远星在无穷远，头动它不动；倾斜时大幅错动的只该是近星和尘埃。实现：每层一个 `parallax` 系数（`params.stars.layers`），最远层 0.05。
  - 💡 **真实星空贴图**（未来，用户 2026-09-23 提出）：按用户所在地与当下时间，把真实夜空投影成最远那层。数据候选：HYG / Yale BSC 星表（公有领域，≈9000 颗肉眼星，程序化画点，几十 KB）优于 ESO 银河全景贴图（CC BY，几十 MB）。需要：定位或时区粗估纬度、恒星时换算、赤道坐标 → 地平坐标；和 §4 太阳高度角共用一套天文算法。进 PLAN backlog，P5 以后。
  - ✅ **2026-09-26 用户**：银河的方向按真实天空，看银河此刻在什么方位就放到屏幕里——**不需要把手机举起来对着天空**（不是 AR）。💡 实现：以天顶为中心的球极投影，上北；画面中心对准银河此刻最高的一段，银河在地平线下时回到天顶。用户原话是「上北下南左西右东」；agent 提醒：抬头看天时北在上方则东在左边，左西右东会让星座镜像（PLAN 未决 13），默认真实朝向，参数可切。
  - 💡 数据（PLAN V1）：NASA SVS Deep Star Maps 2020 的「仅银河」图层（celestial 坐标、equirectangular，4k EXR → JPEG）+ d3-celestial 星表（≤6 等，BSD-3）。署名见 PLAN 本轮假设。
- ✅ **昼夜**（2026-09-26 用户第 4 点）：清晨、白天、黄昏、夜晚按真实时间；白天是蓝天，偶尔有白云。风险：概念图全是夜晚，白天的美术是 agent 发挥的（PLAN 未决 15），设置里有「永远是夜晚」。
- ✅ **真实月相**（用户第 4 点）：反映用户所在地的真实月相，分界线柔和。💡 顺带用上从所在纬度看到的月牙倾角（赤道附近是躺着的「笑脸船」，高纬度是斜的）。
- 阴天：不是单纯变暗，是**云飘过遮挡 + 柔雾层**，亮度降但不消失。晴天开心一点，阴天有点蔫；但对用户的在意不打折（心情影响风味，不影响温度）。

## 5. 空间感与重力感应（用户脑海里的效果，术语先记下）

参考效果：https://pmndrs.github.io/examples/examples/pass-through-portals

想要的：月亮住在一个**有深度的虚拟空间**里，手机倾斜时（重力感应）像**透过一扇窗往一个真实的盒子里看**，而不是在看一张会动的贴图。

- **Portal rendering** / drei `MeshPortalMaterial`：render-to-texture + stencil mask，`blend` 控制「穿过去」。
- **离轴投影 / 非对称视锥（off-axis / asymmetric frustum projection）**：关键。倾斜时如果只是**旋转**相机像全景；必须**平移**相机并**斜切**视锥才像窗口。学名 **Fish Tank VR / head-coupled perspective**（Ware 1993）。
- **Multiplane camera**（迪士尼 1937）：星星分多层不同深度做视差。**Differential parallax**。
- **Atmospheric / aerial perspective**：远处更暗、对比更低、偏冷——远星点用这个，不只是调小。
- **Depth of field / bokeh**：近处星星虚化成圆斑。**Parallax occlusion mapping**：陨石坑有凹陷感但不加几何。
- 重力感应：`DeviceOrientationEvent` / `DeviceMotionEvent`；**iOS 必须由用户手势触发 `requestPermission()`**——产品设计点，要有引导。原始数据抖：**低通滤波 + 弹簧**后再驱动相机。**月亮不要跟手机 1:1 动**，弹簧滞后一点，「有重量」就是从这来的。
- 前摄人脸驱动视差（head-tracking parallax）：效果更强，但有隐私和电量代价——未决。

### ✅ 2026-09-23 拍板：三个旋钮
- **A 窗 = 手机屏幕本身（A2）**：没有实体窗框、没有盒子内壁；屏幕边缘就是边框，边缘处理一定要弱（只有很淡的暗角 + 随倾斜滑动的微弱玻璃反光）。否决过的：A1 实体框（把它关进相框，和「住在你手机的夜空里」冲突）。
- **B 前后关系**：最远三层远星（越远越暗、越冷、视差越小）→ 中景月亮 → 最近几粒漂浮尘埃 / 虚化光斑在月亮**前面**（视差最大，几乎划过屏幕）。**星星从月亮前面飞过是预期效果**，天文上不成立但可爱，接受。
  - 月亮是聊天主体，要占主体位置，感觉是「**隔着屏幕**」——不是挂在天上的贴图。距离先按「一臂远」做，具体数值外置到 `params.ts` 让用户拖。
  - 月亮会**飞远 / 飞近**：飞远时变小变远；飞到最近时充满屏幕，**只剩一只豆豆眼盯着用户**（这是 lean_in 在 intensity 高档的特写，不新增动作原语）。
- **C 倾斜幅度**：要「看得出在动」，不是「察觉不到但立体」。基线：倾斜 20° ≈ 相机横移屏幕宽度的 1/4；月亮用弹簧滞后半拍（有重量）。调参位置 `params.ts`。「穿过去」不做，进 backlog。
- 一句话的感觉：**把月亮养在手机盒子里**——它是个小伙伴，可爱地动。
- 桌面端测试：鼠标位置模拟倾斜（屏幕中心 = 手机放平），调试面板有「自动摇」按钮走一条脚本化的倾斜轨迹（也用于录 GIF）。真机陀螺仪要 HTTPS（iOS 的 `requestPermission` 只在安全上下文可用），P4 加自签证书或隧道。


### 2026-09-26 分层（✅ 用户第 1 点：「盒子里的空间」，无限深，月亮在很近的地方；重力感应下不同角度有立体层次）

## 7. 回应通道（它不说话）

- ✅ **2026-09-26 用户**（取代 2026-09-22 的「拼字（重要）+ 气泡（日常）」）：
  - **月亮的话 = 许多很小的光点（对应流星）从远处不同方向飞来，汇聚成手写体字幕**，不太整齐地漂浮在屏幕上；字是逐渐生成的，不是一起出来；不一定是一颗流星一个字。
  - **用户的话 = 聊天框里「黑洞中浮现的字幕」**：框的边缘把背景光扭曲成爱因斯坦环；重力感应下聊天框只漂浮、不做过度形变，保证能读。
  - **语音**：说话时「黑洞」从小到大生成，加漩涡和远处灯光的扭曲；说得越短框越小；说完等识别时看着小黑洞生成也不无聊；月亮看着它（或看着用户）。
  - **历史**：像星球大战开场字幕那样退远——聊天时旧记录往后退，越来越远、越来越小、越来越淡；翻聊天记录像把远处的字拉近，近处的星星也随之变化；新字不断由星星生成在前方，旧的连同星星退远，循环往复（参考 `moonbao-depth-01/02/03`）。
  - **聊天记录要能看，甚至能搜**（先保证视觉）。
- 💡 光点汇字的做法（PLAN V4）：字形用 Canvas2D 光栅化（任何字体都行，含中文分包网页字体），按笔画的大致书写顺序采样 60–140 个目标点；光点带短尾从 3D 远处沿弧线飞来，错开出发，弹簧过冲后落定；落定后下面淡入清晰的发光字保证可读；字后局部压暗；长消息时月亮飘开给字让位。首字一到就开始飞（目标点在流式输出的同时预计算）。
- 💡 两档防仪式疲劳：日常 = 就近凝结，快（约 1 秒）；重要时刻 = 远方流星，慢而隆重（PLAN 未决 5）。
- 💡 字体：英文手写体候选 Dancing Script / Sacramento / Caveat / Ms Madi；中文霞鹜文楷（都是开源可商用授权）。
- 💡 黑洞气泡的做法：先把背景渲成贴图，气泡边缘按「离边越近偏折越大」采样背景，形成爱因斯坦环 + 一圈细光子环 + 一道更弱的外弧；字画在最上层，永不扭曲；气泡始终正对观察者，倾斜时只平移。
- 💡 聊天记录与搜索（PLAN B2）：全部消息入库（SQLite FTS5，中英文都能搜）；最近约 20 轮在空间里，可以拉近；更早的每一天变成天上一颗记忆星，拉到最远是你的星图；在星图里搜索，命中的星亮起并飞到前面，点开是那天的对话；设置里另有朴素列表版（导出、无障碍）。
- 眼神与动作不能替代必要的明确文字回答。
- 旧想法保留在 backlog：屏幕起雾、擦字浮现。

## 9. 大脑、记忆、低延迟（从姊妹项目继承，已在仓库里）

- 协议：LLM 回复首行紧凑 JSON 头 `{v,a,act,i}`，流式解析到头即驱动表情（比文字先动）；允许分拍；节拍器让文字按阅读速度显现、后续拍等前一拍说完。
- **延迟分层**：Tier 0 纯代码反射（打字→飘近、思考 0.7s→歪头、7s→变暗、断线→变暗/重连→亮起、出错→抖一下，0ms）→ Tier 1 首行头抢跑 → Tier 2（以后）端侧对用户文字做情绪粗判，云回复到达前先摆好姿态。
- prompt caching：人格作稳定前缀，记忆/时间放易变块。快档模型起步（Haiku 级）。**人格回归测例先建后换模型**。
- 记忆：SQLite + 本地 embedding；`follow_up_at`（"明天面试"→次日到期）；到期在开屏时注入 system prompt → 它主动提起；**频控每日 ≤2 次**；久别 ≥3 天归来说「圆了又缺、缺了又圆，一直等着」；过期 3 天作废。
- 危机内容：兜底话术在人格里，不交给小模型。

## 12. 彩蛋（2026-10-04）

- ✅ **很多动作做成让人自己发现的彩蛋**（用户）：不写进引导，不做教程；发现本身就是乐趣。V9 过片的条目默认开启。💡 以后可以有「你发现了 n 个」的小计数（PLAN backlog），等 V9 过后看留存数据再定。
- ✅ **秘密彩蛋**（用户）：一句固定的暗号 → 一段固定的回复 + 特别动作（例：「i'm xxx 小月亮」→「i love you」+ 爱心眼）。用户把暗号告诉爱人 / 朋友，他们在自己的手机上说，它就会回。要求：暗号加密、无法从代码解出；回复 base64，不懂技术的人一眼看不出。
  - 💡 做法（PLAN V9-E）：暗号只以盐化 SHA-256 存在 `persona/eggs.json`，盐 `EGG_SALT` 在 `.env`（不提交）；回复 base64；匹配前归一化（NFKC、小写、去全部空白和标点），文字和语音同一匹配；命中就跳过 Jev 和 LLM，服务端直接演出 + 隆重档写字；不进记忆。暗号由用户本机 `npm run egg -- add` 加入，不回显、不打印，agent 全程看不到。
  - 爱心眼只有这里能触发：它在替你传话，不是它自己爱上用户。
